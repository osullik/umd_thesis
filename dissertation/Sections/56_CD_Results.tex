\section{Analyze Results, Develop Theoretic Explanation and Iterate}
\label{section:56-CD-Results}
This results section and the following discussion demonstrate how an engineer would use the population segmentation benchmark problem as a component of the \gai benchmark framework to evaluate several shortlisted system configurations for procurement. 
The engineer is aware of analyst requirements for their \gai tasks to complete within a limited timeframe and a willingness of analysts to sacrifice the optimality of the solution for a faster result.
First, we describe the specifics of the experiment setup, and second, we describe the results. 

\subsection{Demonstration Setup}
We implement the \gai population segmentation benchmark in Python 3.11.5 and make the environment\footnote{\scriptsize \url{https://github.com/osullik/umd_thesis/tree/main}} details available.
The implementation follows the design from figure~\ref{figure:cd-apparatus}, except that the benchmark server is located on the system under test and that the polling is done passively by checking the timestamps of an interim-results folder after the experiment. 
To run the benchmark, the researcher specifies the problem and dataset. 

We provide experiment specifications for the $28$ experiments listed in table~\ref{table:cd-experiments} as \texttt{json} files\footnote{\scriptsize available at: \url{https://github.com/osullik/umd_thesis/tree/main/gaib/experiment_definitions}} that the \texttt{benchmark server} uses to create the experiments.
The process is entirely automated to maximize usability, from requesting a benchmark problem from the server until the server provides the data and figures in the return report. 
The experiments are run on a single configuration of hardware and supporting software\footnote{\scriptsize 2023 Apple Macbook Pro; $12$ Core M2 Max Processor, 32GB Hynix LPDDR5 RAM; MacOS 14.1-Darwin-23.4.0}, with only the implementation varying in the approach to the problem.
We limit our choice of implementations to the NetworkX library to standardize the representation and ETL processes between implementations. 
The static approach uses the NetworkX \textit{Louvain Communities}\footnote{\scriptsize \url{https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_communities.html}} implementation and the incremental use the NetworkX \textit{Louvain Partitions}\footnote{\scriptsize \url{https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_partitions.html}} library, which iteratively yields communities at decreasing granularity.

\subsubsection{Effectiveness Results}
Examining the number of predicted versus ground truth communities shows that NMI increases as the number of predicted communities increases but that there is a concurrently increasing delta between the number of predicted and ground truth communities~(figure~\ref{fig:cd-results-effectiveness-communities}). 
Both of these covary with the size of the graph. 
Examining the effectiveness of the iterative algorithm over each increment in Figure~\ref{fig:cd-results-effectiveness-community-lines} shows that while the NMI converges to a higher value and the number of communities decreases as iterations continue, they do not `improve' monotonically over time.
