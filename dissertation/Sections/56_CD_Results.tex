\section{Analyze Results, Develop Theoretic Explanation and Iterate}
\label{section:56-CD-Results}
This results section and the following discussion demonstrate how an engineer would use the population segmentation benchmark problem as a component of the \gai benchmark framework to evaluate several shortlisted system configurations for procurement. 
The engineer is aware of analyst requirements for their \gai tasks to complete within a limited timeframe and a willingness of analysts to sacrifice the optimality of the solution for a faster result.
First, we describe the specifics of the experiment setup, and second, we describe the results. 

\subsection{Experiment Setup}
We implement the \gai population segmentation benchmark in Python 3.11.5 and make the environment details available\footnote{\scriptsize \url{https://github.com/osullik/umd_thesis/tree/main}}.
The implementation follows the design from Figure~\ref{Figure:cd-apparatus}, except that the benchmark server is located on the \ac{SUT} and that the polling is done passively by checking the timestamps of an interim-results folder after the experiment. 
To run the benchmark, the researcher specifies the problem and dataset. 

\input{Figures/Diagrams/19_experiment_specification}

We provide experiment specifications for the experiments shown in Figure~\ref{Figure:experiment-specification}, and listed in Table~\ref{Table:cd-experiments} as \texttt{json} files\footnote{\scriptsize available at: \url{https://github.com/osullik/umd_thesis/tree/main/gaib/experiment_definitions}} that the \ac{BS} uses to execute the experiments.

% a \textit{Baseline} system to represent the `start point' of a prototype \gai system, a \textit{CPU} system to represent a \ac{HPC} cluster and a \ac{GPU} system to represent a \ac{HPC} system with a \ac{GPU} installed.
We test the three \ac{SUT}s.
The \textit{Baseline} system is a personal laptop computer, representing the existing capability of the Engineer's team\footnote{\scriptsize 2023 Apple Macbook Pro; $12$ Core M2 Max Processor, 32GB Hynix LPDDR5 RAM; MacOS 14.1-Darwin-23.4.0}.
The \textit{CPU} system is a single-socket of a \ac{HPC} cluster\footnote{\scriptsize $16$ Core Intel Xeon Silver 4216 3.2GHz, 32GB RAM; RedHat Enterprise Linux 8.9} and the \ac{GPU} system is a single GPU hosted on a \ac{HPC} cluster\footnote{\scriptsize As per \ac{CPU} system, with addition of $1\times$ NVIDIA RTXA5000 (8192 Cores, $24$GB GDDR6, $768$DB/s memory bandwidth), \ac{CUDA} v12.4}.
We limit our choice of implementations to the NetworkX library to standardize the representation and \ac{ETL} processes between implementations. 
The static approach uses the NetworkX \textit{Louvain Communities} implementation\footnote{\scriptsize \url{https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_communities.html}} and the incremental use the NetworkX \textit{Louvain Partitions} library\footnote{\scriptsize \url{https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.community.louvain.louvain_partitions.html}}, which iteratively yields communities at decreasing granularity.
