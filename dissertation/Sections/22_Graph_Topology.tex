\section{Graph Topology}
\label{section:22-graph-topology}
Graphs fit into core classes (scale-free, mesh, random) based on size, shape, topological structure, and construction method. 
We begin by addressing the classes of graphs that occur in the real world and then discuss synthetically generated graphs, which can be constructed randomly or using a prior distribution.

\subsection{Real-World Graphs}
This section will first identify the `natural' graph classes derived from real-world phenomena like email records, chat logs, network logs, road maps, protein structures, or any extensive collection of problems that can be represented as a graph.

\subsubsection{Scale-Free Graphs}
\define{Scale-Free Graph}{A naturally occurring graph class characterized by a distribution of vertex degrees that follow a power-law distribution. }

Scale-free graphs are common in social networks because as the number of vertices increases over time, new vertices preferentially attach to vertices that already have high degrees~\cite{Barabasi1999a}. 
They tend to have a small diameter, a significant variance in neighborhood size, and a `global-neighborhood' characteristic where all vertices are in the same neighborhood within a few hops.
These characteristics are often amalgamated and termed the `small world' property.

\subsubsection{Mesh Graphs}
\define{Mesh Graph}{A naturally occurring graph class characterized by a flat, regular degree distribution.}

Mesh graphs are often derived from physical phenomena like road networks, and so new vertices tend to extend the graph outwards~\cite{Beamer2015}.
They tend to have a large diameter, a slight variance in neighborhood size, and a `local-neighborhood' characteristic where only a small subset of vertices are reachable within a few hops of any given vertex.

\subsection{Synthetic Graphs}
Real-world graphs offer realistic test inputs for graph algorithms.
However, some domains need more data to support robust testing, especially regarding performance on irregular distributions. 
As a solution, synthetic graphs can be mathematically or imitatively generated to provide simple graphs for testing and evaluation. 

\define{Synthetic Graph}{A graph that is generated by using a mathematical function or to imitate an existing distribution}

\subsubsection{Mathematically Generated Synthetic Graphs (Random Graphs)}
Multiple mathematical functions can generate synthetic graphs, typically by adding vertices and edges following some set of heuristics to reflect a given probability distribution.
Notable generators include the Erd\H{o}s-R\'enyi generator to create \textit{Uniform Random Graphs}~\cite{Erdhos1960}, the \ac{RMAT}~\cite{Chakrabarti2004} and \textit{Kronecker}~\cite{Leskovec2010} generator to generate scale-free graphs.
Mathematically generated random graphs can approximate real-world graphs but, because of the generation process's structural simplifications, provide a sub-optimal substitute for actual graphs' irregularities. 

\subsubsection{Imitatively Generated Synthetic Graphs (Imitative Graphs)}
For privacy and confidentiality reasons, many graph datasets are irrelevant for research and development. 
Active research in privacy preservation and synthetic graph generation seeks to summarize a real-world graph statistically and then use that summary as the input to a synthetic graph generator so that the synthetic graph will have the same topological properties as the original without the confidential information. 
Imitative graph generation methods use input features like \textit{Triangle Histograms, K-Hop Neighbor Histograms, Random Walk Histograms} and \textit{Number of Edges} to produce topologically similar graphs~\cite{Zahirnia2024}.
Their process is inherently lossy and has only been tested on tiny graphs (tens of thousands of edges), so it is unreliable for wide use.


\subsection{Summary}

The core graph topology classes discussed above (scale-free, mesh, mathematically generated, imitatively generated) each have inherent benefits and drawbacks for graph processing. 
We view these classes as representatives of the kinds of `datasets' relevant to \gai. 
As such, a good \gai benchmark should cover each class to enable a longitudinal view of expected performance.
