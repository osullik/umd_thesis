\section{Graph Representations}
\label{section:21-graph-representations}
The tradeoff between memory efficiency and lookup efficiency is a core tension in graph processing and many of the attempts to accelerate the efficiency of graph algorithms focus on balancing these two dimensions.
This section introduces key concepts of graph representation, including storage, abstractions and primitive operations as the primary levers used to balance memory consumption and compute efficiency. 

\subsection{Graph Storage}
A graph's storage format has a direct impact on the space it consumes in memory, the speed of operations over it and the operations it can perform.
The \textit{Adjacency Lists} have a small storage footprint, but slow lookup times, with \textit{Adjacency} and \textit{Incidence Matrices} having reciprocal properties. 
Modern efforts show how \textit{compressed representations} can be used to balance memory and computational overheads.

\subsubsection{Adjacency Lists}
The adjacency list representation (Figure~\ref{figure:graph-adj-list}) uses a linked list or array to store a graph.
The first entry in each line is the source vertex and each subsequent entry indicates an edge exists to the listed vertex.
Adjacency lists can represent a directed or undirected graph. 
Representing weights as part of the topology is possible using a list of tuples and attribute information is typically stored separately.
Adjacency lists have a small memory footprint ($\mathcal{O}(|V|+|E|)$), but finding a particular edge is expensive -- linear in the number of vertices ($\mathcal{O}(|V|)$) in the worst case.

\subsubsection{Adjacency Matrices}
An adjacency matrix (Figure~\ref{figure:adjacency_matrix}) uses a $|V|\times|V|$ matrix to represent the graph.
The presence of a $1$ at location $V_{i},V_{j}$ indicates that an edge exists from vertex $i$ to vertex $j$.
They can represent directed or undirected graphs, and the value at position $V_{i},V_{j}$ can be changed to represent the weight of the edge. 
Attributes are stored separately from the matrix. 
\textit{Adjacency matrices} have a memory footprint of $\mathcal{O}(|V|^{2})$ but a constant lookup time ($\mathcal{O}(1)$).
One of their major drawbacks is the requirement to store all the $0$s where edges to not exist--essentially useless information.

\subsubsection{Incidence Matrices}
Edge Matrices (Figure~\ref{figure:incidence_matrix}) use a $|V|\times|E|$ matrix to represent the graph. 
An edge is represented with a $-1$ at position $E_{i},V_{j}$ to indicate the source and a $1$ at position $E_{i},V_{k}$ to indicate the destination. 
Incidence matrices are the most expressive representation and can encode \textit{multi-graphs} and \textit{hyper-edges}.
Weights can be expressed by modifying the numbers in the matrix and the attributes are typically stored separately. 
The space complexity of an incidence matrix is $\mathcal{O}(|V|\times|E|)$ and so for sparse graphs may be more space-efficient than an \textit{adjacency matrix} but in general will consume significantly more memory in the typical case where $|E|>>|V|$.
The lookup time for edge existence is slower than for an \textit{adjacency list}. 
To find an edge connecting two vertices, we need to scan the entire edge list for each vertex and locate which edge(s), if any, are incident to both vertices, reducing to a complexity of $\mathcal{O}(|E|)$.

\subsubsection{Compressed representaions}
To balance expressiveness, memory consumption and computability, numerous compressed representations have been developed. 
The dominant choices are the Compressed Sparse Row (CSR) and Compressed Sparse Column (CSC) formats (Figure~\ref{figure:csr}).
The CSR format uses three lists to compress the rows of a sparse matrix, like an adjacency matrix~\cite{Bulucc2009}. 
First, the \textit{value list} contains every nonzero value of the matrix (the existence of an edge), and so has a length of $|E|$ in a directed adjacency matrix. 
The \textit{Row Pointer} list contains the index of each position in the \textit{value list} that is associated with a new row.
The \textit{Column Indices} list contains the column index of each value in the \textit{value list} from the original sparse matrix.
So in figure~\ref{figure:csr}, the values associated with the \textbf{A} vertex (row $0$ of the adjacency matrix) are at positions $[0,1]$ in the value list in figure~\ref{figure:csr}. 
We derive this by looking at the row index in figure~\ref{figure:csr} and seeing that the second row begins from index $2$.
Knowing that the first two values in the value list are the sources of our edges, we know that the first two values in the column index in figure~\ref{figure:csr} are the destinations $[1,2]$.
In the adjacency matrix (figure~\ref{figure:adjacency_matrix}), column $1$ is for vertex \textbf{B} and column $2$ is for vertex \textbf{C}. 
The CSC format reverses the function of the row and column indices so that the columns are compressed.
The space efficiency for CSR/CSC format is $\mathcal{O}(|V|\log(nnz)+nnz\log(|V|))$ for an adjacency matrix of $|V|$ vertices~\cite{Bulucc2009} and takes $\mathcal{O}(\log(nnz))$ time to check the existence of an edge where $nnz$ is the count of non zero entries in the matrix.
More complicated representations exist which are capable of compressing the graph representations even further. 
But, in general, the more aggressive a compression scheme, the more computation overhead is introduced by the encoding/decoding process~\cite{Shun2015}.
