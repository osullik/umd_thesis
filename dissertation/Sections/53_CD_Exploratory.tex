\subsection{Implementation Observations}

\textbf{Algorithmic Weaknesses Exist in Community Detection.}
Many approaches require the number of communities, clusters, or partitions to be known in advance or they must run an algorithm like K-Means multiple times to discover the optimal number of communities (\cite{Kernighan1970, Reichardt2004, Ng2001, White2005, Yang2016, Wang2017}), significantly increasing the computational cost when the number of communities is large. 
Knowing the number of communities a priori does not reflect the discovery process expected in the real world~\cite{Regli2022a}.
Recursive-bisection partitioning approaches fail when there are three equally sized communities at a given recursion level; at least one will be mistakenly grouped with another and will usually be split across both. 
Greedy-agglomerative clustering approaches fail when two cliques are connected by nodes of a lower degree than the clique, pulling the `bridge' nodes into the cluster they bridge to rather than their own. 
Most approaches cannot assign a vertex to multiple communities because of the underlying assumptions about clustering and partitioning, so overlapping communities rely on graph attributes for effective community detection on heterogeneous graph structures~\cite{Reichardt2006}.
The most popular implementation (Louvain~\cite{Blondel2008}) has been shown to produce disconnected communities when the shape of the input graph contains hierarchical community structures that contain cliques joined by bridge nodes~\cite{Traag2019}.

\textbf{Dynamic Processing relies on Short Batch Latency.}
The inputs to dynamic graph processing algorithms are either a collection of related graphs describing the same problem at $T$ time slices or may have a stream of updates to reflect when a vertex is added, deleted, or updates its properties.
Consequently, the task is typically to identify when a community changes or which communities persist for extended periods (\nrscomment{is this an example or an alt defn? i.e. do you need to add "i.e."/"e.g."?} the co-traveler problem).
Many dynamic processing approaches batch the updates and apply a static community detection approach at each iteration, then calculate the similarity in communities between each timestep, with more efficient implementations keeping the prior state in memory to reduce computation~\cite{Rossetti2018}.
These batching approaches fail in real-time settings where the batch latency exceeds the length of each timestep $T$.

\textbf{Community Detection is suitable for Approximate and Incremental approaches.}
Clustering, partitioning, and \ac{CD} are typically implemented as iterative algorithms that converge to a heuristically optimal solution but can return some information at each iteration step and are vulnerable to local maxima.

\textbf{Weights and Attributes are critical for segmenting fuzzy and overlapping communities.} 
Graph partitioning, clustering, and community detection are traditionally topology-only algorithms. 
However, access to some states, like the sentiment of an edge~\cite{Yang2007}, or the weights associated with edges~\cite{Rosvall2008} yield superior segments. 
The same is true of attributes, and prior knowledge about group membership of some nodes dramatically improves the identification of overlapping and fuzzy communities~\cite{Zhang2013}. 

\subsection{Outputs}
Completing the exploratory analysis through a literature review reveals the bottlenecks that impact population segmentation approaches and that will guide hypothesis development in the next step. 

\textbf{Efficiency Bottlenecks.}
We expect that increasing the number of vertices and the number of edges will both degrade the efficiency of the approaches, given the worst-case complexity estimates in table~\ref{table:cd-survey}.

\textbf{Effectiveness Bottlenecks.} 
The effectiveness of community detection approaches is vulnerable to fuzzy and overlapping communities, denser graphs, and when `bridges' exist between cliquey structures.

\textbf{Friction Points.} 
We identify additional friction points, including the requirement for a priori knowledge of the number of communities by many approaches, the lack of support for overlapping communities, and the lack of work in dynamic \ac{CD} benchmarks.
